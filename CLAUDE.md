# MM native: notes for working on this repository

Static recompilation of Mega Man 1-6 (NES) to native Win64, plus a launcher.
See README.md for the user-facing description.

## Layout
- `src/` runtime shared by all games. `nes.c` = memory map, mappers (UxROM 2, MMC1 1, MMC3 4),
  PPU (scanline renderer), APU, interrupts, the reference interpreter (`interp_gen.inc`,
  generated by `tools/gen_interp.py` from `tools/m6502.py`). `host_win32.c` = game front end.
  `host_test.c` = headless Linux test host.
- `games/mmN/` generated by `tools/recomp.py` + `tools/embed.py`. Do not hand-edit.
- `launcher/` launcher; `core.c` is platform independent (renders 320x200, synthesizes audio),
  `win32.c` is the Windows shell. `launcher/test.c` renders frames headlessly.
- `coverage/coverage_mmN.bin` code-coverage maps (4 slots x NB8 banks x 8 KB) from interpreter runs.

## ROMs
Not in the repo. Expected next to the exes / one folder above the repo for `make regen`.
Identified by MD5 (whole file or without the 16-byte header); table in README.md and
`launcher/win32.c`. The test host takes a ROM path on the command line.

## Toolchain (cloud session)
- Linux gcc for the test host: `gcc -O2 -w -o mmtest src/nes.c src/host_test.c`
  and `gcc -O2 -w -Isrc -DRECOMP -o mmtest_rcN src/nes.c src/host_test.c games/mmN/rc_*.c`.
- Windows exes are cross-compiled with llvm-mingw (download the ubuntu x86_64 ucrt tarball from
  github.com/mstorsjo/llvm-mingw releases): `x86_64-w64-mingw32-gcc`, `x86_64-w64-mingw32-windres`.
  Game exe: `src/nes.c src/host_win32.c src/osd.c src/md5.c games/mmN/*.c appN.res.o -mwindows -lwinmm -static`.
  Launcher: `-Isrc launcher/win32.c launcher/core.c src/md5.c launcher.res.o -mwindows -lwinmm -static`.

## Verification (do this after any runtime or recompiler change)
1. CPU: `mmtest nestest nestest.nes` matches nestest.log; blargg instr_test-v5 all pass
   (test ROMs from github.com/christopherpow/nes-test-roms, not in the repo).
2. Per game: run the interpreter (`mmtest run ROM 15000 -i script -h a.txt`) and the recompiled
   build (`mmtest_rcN ... -h b.txt`) with the same input script; `a.txt` and `b.txt` (per-frame
   RAM + framebuffer hashes) must be identical, also with `--extra 4000 --nolimit` (boost).
   Input scripts: `tools/mkinput2.py seed prefix.txt start_frame total_frames`; stage-select
   prefixes are in README / git history. `-c cov.bin` records coverage; feed it to recomp.py.
3. Original mode must not change: interpreter hashes with boost off should match earlier runs.

## Conventions
- Boost = 4000 extra CPU-only scanlines after line 240 (APU frozen) + no 8-sprite limit.
- Game exes take `--fullscreen --scale N --volume 0-100 --boost --launcher --rom path`.
- Keep the repo private (generated code is ROM-derived). Never commit .nes files.
