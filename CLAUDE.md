# MM native: notes for working on this repository

Static recompilation of Mega Man 1-6 (NES) to native Win64, plus a launcher.
See README.md for the user-facing description.

## Layout
- `src/` runtime shared by all games. `nes.c` = memory map, mappers (UxROM 2, MMC1 1, MMC3 4),
  PPU (scanline renderer), APU, interrupts, the reference interpreter (`interp_gen.inc`,
  generated by `tools/gen_interp.py` from `tools/m6502.py`). `host_win32.c` = game front end.
  `host_test.c` = headless Linux test host. `filters.c` = CRT and xBRZ upscaling filters
  (presentation only; `third_party/xbrz/` is C++, GPLv3, called through `src/xbrz_glue.cpp`).
- `games/mmN/` generated by `tools/recomp.py` + `tools/embed.py`. Do not hand-edit.
- `launcher/` launcher; `core.c` is platform independent (renders 320x200, synthesizes audio),
  `win32.c` is the Windows shell. `launcher/test.c` renders frames headlessly.
- `coverage/coverage_mmN.bin` code-coverage maps (4 slots x NB8 banks x 8 KB) from interpreter runs.

## ROMs
Not in the repo. Expected next to the exes / one folder above the repo for `make regen`.
Identified by MD5 (whole file or without the 16-byte header); table in README.md and
`launcher/win32.c`. The test host takes a ROM path on the command line.

## Toolchain (cloud session)
- Build the xBRZ objects first: `g++ -O2 -c third_party/xbrz/xbrz.cpp -o xbrz.o`, `g++ -O2 -c src/xbrz_glue.cpp -o xbrz_glue.o`.
- Linux gcc for the test host (JB = `src/jukebox.c src/music_core.c src/md5.c src/filters.c xbrz.o xbrz_glue.o -lm -lstdc++`):
  `gcc -O2 -w -Isrc -o mmtest src/nes.c src/host_test.c src/wide_mm*.c $JB`
  and `gcc -O2 -w -Isrc -DRECOMP -o mmtest_rcN src/nes.c src/host_test.c src/wide_mm*.c $JB games/mmN/rc_*.c`.
- Windows exes are cross-compiled with llvm-mingw (download the ubuntu x86_64 ucrt tarball from
  github.com/mstorsjo/llvm-mingw releases): `x86_64-w64-mingw32-gcc`, `x86_64-w64-mingw32-windres`.
  Game exe (link with `x86_64-w64-mingw32-g++`, C sources after `-x c`): `-x c src/nes.c src/host_win32.c src/osd.c src/md5.c src/jukebox.c src/music_core.c src/filters.c games/mmN/*.c -x none xbrz.o xbrz_glue.o appN.res.o -mwindows -lwinmm -static`
  plus `src/wide_mmN.c` (`games/mmN/rom_data.c` names the game's widescreen provider).
  Launcher: `-Isrc launcher/win32.c launcher/core.c src/md5.c launcher.res.o -mwindows -lwinmm -static`.

## Verification (do this after any runtime or recompiler change)
1. CPU: `mmtest nestest nestest.nes` matches nestest.log; blargg instr_test-v5 all pass
   (test ROMs from github.com/christopherpow/nes-test-roms, not in the repo).
2. Per game: run the interpreter (`mmtest run ROM 15000 -i script -h a.txt`) and the recompiled
   build (`mmtest_rcN ... -h b.txt`) with the same input script; `a.txt` and `b.txt` (per-frame
   RAM + framebuffer hashes) must be identical, also with `--extra 4000 --nolimit` (boost).
   Input scripts: `tools/mkinput2.py seed prefix.txt start_frame total_frames`; stage-select
   prefixes are in README / git history. `-c cov.bin` records coverage; feed it to recomp.py.
3. Original mode must not change: interpreter hashes with boost off should match earlier runs.

## Widescreen (extended mode)
- Generic part in `src/nes.c` (`wide_line`, `wide_end_frame`): draws `wide_ext` extra columns per side into
  `wide_left/right` from a `WideProvider` (begin: camera from RAM; tile: world tile -> tile+palette, 0 = dark).
  Lines whose scroll is not within 24 px of the camera stay dark. Tiles actually shown are sampled per line;
  at frame end the provider must match 85% or the sides are blanked. Also searches a vertical row offset.
- Providers: `src/wide_mm1.c` .. `wide_mm6.c` (format notes in each file), named in `rom_data.c` via `tools/embed.py`.
- Test: `mmtest run ROM N -i script --wide 72 --prov N -s shot 100` (screenshots include the extra columns;
  `--prov` picks the game's provider, default 2); `--wlog f` writes per-frame match %, stderr prints
  `wide level=.. active=..`. Build with `-DWIDE_DEBUG=frame` to print mismatches, `-DWIDE_FORCE` to skip the check.
  Interp vs recompiled hashes must also match with `--wide`.
- Objects in the extension: optional provider callback `objects()` returns sprites (x relative to the
  256-px picture) drawn only outside 0..255 (`wide_sprites_line`); MM2 only so far (`wide_mm2.c`: spawned
  slots in full + unspawned whitelisted types from the stage's object lists). Test host: `--noobj`,
  `--ghostall` (show every unspawned object), `-P file` per-frame pokes ("frame addr val", e.g. to walk Mega
  Man through a stage by poking his x), `--vdump file frame` (CHR 8 KB + palette + RAM, for galleries).
- Go-right test bot used for the providers: hold Right, jump and shoot; poke Mega Man's HP each frame
  (MM1 `6A=1C`, MM2 `6C0=1C`, MM3 `A2=9C`, MM4/5 `B0=9C`, MM6 `3E5=1B`).
- HUD relocation (`hud_move`, `hud_detect` in `nes.c`): energy-bar columns (Y 24..72; full = 7 sprites, low energy
  = only the bottom rows, accepted if a bar was seen at that X/attr in the last 120 frames) are drawn
  at new X in wide modes; player bars (X<=24) only when `wide_ext > 0`, boss bar (X 25..64) always.
  Test host: `--hud` (prints `hud_seen`: bit0 player, bit1 boss), `--hudlog f` per-frame bits; `-DHUD_DEBUG` prints misses. Boss-bar pokes for testing:
  MM1 `3E=01`, MM2 `B1=01 6C1=14`, MM3 `B3=80`, MM4 `132=80`, MM5 `2F=80`, MM6 `642=01 3ED=10`.
- Debug hooks in the test host: `-w ppu.txt` logs PPU register writes with PC, `-r ram.bin` dumps RAM per frame.

## Jukebox (arranged music mod)
- `src/music_core.c` includes `nes.c` a second time with every global renamed (`src/music_rename.h`,
  regenerate with `python tools/gen_music_rename.py` after adding a global to nes.c). It runs only a
  sound driver: `music_core_call(addr, A)` runs a subroutine to RTS; `music_core_frame_time()` advances
  one frame so its APU makes samples.
- `src/jukebox.c`: ROM MD5 table, driver table (MM1/2: play $9000/$8000, request +3, pointer table;
  MM3-6: play $8000, request $8003, count $8A40, big-endian pointers $8A43), track names, playlist.
  `jukebox_skip.h` is generated from `mmtest musicscan ROM 40` (silent / under ~5 s).
- Game music is muted with `apu_gate` (nes.c mixer): only SFX channels pass, from the driver's mask
  (`$EF` MM1/2, `$CF` MM3-6; bit 0 pulse 1 .. bit 3 noise). DMC muted.
- Test host: `mmtest music ROM id(hex) secs out.raw`, `mmtest musicscan ROM secs`,
  `run ... --juke other.nes id(hex) [--jukenomix] -a out.raw`, `--sndlog bank:addr file` logs
  driver requests (e.g. `16:8003` for MM3), `-w` also logs APU writes with the writer's bank.

## Filters (upscaling)
- `filter_render(mode, src, sw, sh, dst, dw, dh)` draws straight at window size; `host_win32.c` runs the jobs on a
  small thread pool (`filter_set_parallel`). F7 cycles, `--filter 0|1|2`, launcher LOOK panel (`launcher.ini filter`).
- CRT: linear light, gaussian beam per scanline (width grows with brightness), halation, aperture grille,
  barrel curvature + rounded corners + vignette (per-pixel lookup cached per size). xBRZ: scale 2..6, then bilinear.
- Test: `mmtest filter ROM in.ppm mode dw dh out.ppm` (ROM only satisfies the arg parser; prints ms per frame).

## Conventions
- Boost = 4000 extra CPU-only scanlines after line 240 (APU frozen) + no 8-sprite limit.
- Game exes take `--fullscreen --scale N --volume 0-100 --boost --wide 0|1|2 --filter 0|1|2 --jukebox --launcher --rom path`.
- Keep the repo private (generated code is ROM-derived). Never commit .nes files.
